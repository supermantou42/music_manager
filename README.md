# 声笺 Music Manager 验证原型

## 大列表与批量流程

主界面集中展示原文件封面、歌名、歌手、专辑、格式/时长、歌词核验、元信息差异和替代搜索结果。原文件封面与候选封面分列显示，加载失败时显示占位图。支持关键词、状态筛选和每页1000首；全选只选择当前页，跨页勾选会保留。

“自动核验并搜索差异”处理勾选歌曲：无转写时运行本地ASR，已有转写时复用结果，然后对存在字段缺失、正文差异等问题的歌曲搜索替代。也可单独批量核验、批量搜索。后台逐首更新进度，停止按钮等待当前歌曲结束后停止后续任务。结果保存在 data/library.json，重新打开会恢复歌曲与搜索结果；不会自动恢复中断的任务。

搜索区分尚未搜索、没搜到、搜到合适替代、搜到结果不合适、搜索失败、已采纳替代。初步合适性检查包括歌名、歌手、版本、12秒内时长差和有效歌词；有可用ASR时，歌词相似度低于70%需要复核。规则是筛选依据，不保证真实版本一致，采纳仍由用户决定。参考信息出现专辑/歌手等差异时单独标记，不直接认定源标签错误。

点击目标区域才打开对应的小弹窗：封面显示大图，歌名/歌手/专辑显示元信息，核验状态显示原歌词和带时间戳的转写，差异标记显示差异，搜索状态/建议候选显示替代结果。候选一次显示一个，可切换并手动采纳。整行点击不触发详情，点击弹窗外部或按 Esc 关闭；支持键盘 Enter/空格打开及 Tab 在弹窗内切换。不会自动改动源音乐或音频内嵌标签。载入验证样本会一并加载历史在线候选，避免重复联网查询。

`npm.cmd test` 包含20项检查，`node verify-overview.cjs` 验证列表概况、缓存候选采纳和真实内嵌封面接口。

Windows + Electron，Node 后台使用本机 FFmpeg/ffprobe。无需 Python。此版本优先验证扫描和真实 ASR；React、SQLite、标签写回和 Qwen 文本判断尚未接入。

## 启动

```powershell
npm.cmd install
npm.cmd start
```

浏览器备用模式：`npm.cmd run dev`，打开 http://127.0.0.1:4173，手动输入目录。

项目已下载官方 llama.cpp b11552 CPU 运行包，使用 `powershell -ExecutionPolicy Bypass -File .\start-asr.ps1` 启动。CPU 版用于连通验证，后续可替换为 CUDA 版利用 RTX 4060 Ti。ASR 进程在独立终端运行，关闭客户端不会关闭它。

## ASR

使用支持 Qwen3-ASR 的新版 llama.cpp，在单独终端运行：

```powershell
llama-server.exe -m D:\models\gguf\Qwen3-ASR-1.7B-Q8_0.gguf --mmproj D:\models\gguf\mmproj-Qwen3-ASR-1.7B-Q8_0.gguf --host 127.0.0.1 --port 8081 -c 8192
```

界面勾选歌曲后核验。使用 FFmpeg 在150–3500Hz频段解码16kHz单声道PCM，每25ms计算RMS，平滑后寻找比附近背景低至少2.5dB的能量低谷。最短3秒、目标8秒、最长18秒，没有低谷时按最长长度回退。片段连续覆盖整曲，无重叠；静音片段跳过转写。原歌词不发给ASR。每段保留全曲起止时间和转写正文，界面显示时间范围，导出额外保存 `.asr.rough.lrc`。时间戳为片段起点，一个片段可能有多句歌词，伴奏也会影响边界；尚未自动检查原LRC偏移。相似度是去除时间戳、标点及署名后的字符编辑距离，最多处理30分钟音频。

“声学粗切分预览”只计算边界，无需ASR服务。`node verify-acoustic.cjs` 对前面十首样本验证边界，并对《告白气球》执行真实分段ASR；结果保存到 validation/music-sample-10/acoustic-report.md。

切片识别结果统一按 LRC 形式显示：`[mm:ss.xx]识别文本`，每行对应一个切片，空结果也保留时间戳。每次核验后自动保存到 `data/asr/<本次任务ID>/`：`clips/*.wav` 为切片，`transcript.lrc` 为结果，`segments.json` 记录起止时间与对应音频文件，`index.md` 可点击试听切片。现有9段样例位于 `validation/music-sample-10/segmented-result/`。时间戳是原曲中片段的起点，不为同片段中的多句文本伪造独立时间戳。

主界面已接入网易云与 QQ 在线元信息和歌词搜索，可预览候选并手动采纳到当前任务。Mock 接口仅供离线测试。输出复制原文件，歌词作为 `.lyrics.txt` 保存；不转码、不修改源文件、不写回标签。相同字节文件在同一导出批次去重；已有输出不覆盖。扫描跳过符号链接，任务持久化到 data/library.json。歌词文本文件写入失败时原音频副本可能已经存在，界面会报告错误。

建议先选 3–5 首包含中文/粤语/英语、正确/错误/无歌词的歌曲验证，查看原歌词与真实转写。没有真实歌曲样本时不能判定模型识别准确率。

`npm.cmd test` 运行命名与比对检查。

元信息接口实现与来源说明见 [METADATA_INTEGRATION.md](METADATA_INTEGRATION.md)。在线候选排序测试：`node --test tests.cjs metadata-tests.cjs`。首次使用需有 `metadata-bridge/metadata-bridge.exe`，可通过该目录的 build.ps1 重建。

## D:\Music 抽样验证

`node sample-validation.cjs` 按格式与外置 LRC 情况固定种子抽取 10 首，逐首保存真实 ASR 结果。完成后运行 `node finalize-validation.cjs`，按最新规则去除署名影响、标记重复转写异常并生成报告。输出位于 `validation/music-sample-10/`，不修改源音乐。客户端点击“查看 10 首抽样”加载保存结果，无需重复推理。

## 试听

列表中的 ▶ 播放本地原曲，底部播放器支持暂停、进度拖动和音量调节。歌词核验弹窗内可以播放原曲或每个声学切片，查看对应识别结果。关闭详情不停止播放；底部 ✕ 停止试听。原曲通过本机接口流式读取并支持 HTTP Range；浏览器无法解码时生成24位PCM WAV兼容副本，保留源采样率与声道，避免有损重编码。切片按原曲时间范围生成 WAV，试听缓存位于 data/audio-preview/，不修改源音乐。暂未提供在线候选录音试听。`node verify-audio.cjs` 验证原曲字节范围、切片及兼容试听接口。


## 语种与歌词对比播放器

核验时保留 Qwen ASR 返回的语种标签，按有文本片段时长汇总。历史任务可在元信息/歌词弹窗点击“识别语种”，抽取25%、50%、75%位置各最多10秒；无标签时显示未识别，不根据歌名猜测。混合语种结果仅为辅助判断。

试听自动打开歌词小弹窗，切换原歌词、粗时间戳转写或在线候选不重启音频。随播放高亮滚动，点击歌词跳转；时间调整正数表示延后歌词，仅影响当前试听，不修改LRC。无时间戳歌词显示正文。切片试听以原曲的绝对时间显示歌词，播放解码保留采样率与声道；用于ASR的16kHz单声道切片另行保存。

开源方案：APlayer提供HTML5音乐播放器与LRC界面（MIT）；mpv支持Windows WASAPI及JSON IPC，更适合作为后续桌面音频内核。Electron客户端已接入mpv，浏览器开发模式继续使用HTML5 audio。

验证：npm.cmd test共24项通过；node verify-audio.cjs验证原曲字节范围和PCM兼容播放。播放器界面未完成自动化视觉验证。


## mpv 播放内核

Electron通过独立隐藏进程与Windows命名管道JSON IPC控制mpv。桌面端直接解码原文件，切片使用start/end范围，不生成转码副本。界面提供暂停/重播、精确跳转、音量；歌词高亮使用mpv时间，候选切换不重载音频。退出客户端结束其mpv子进程。

Windows默认WASAPI共享输出，不启用独占模式，不额外加均衡器或响度处理。采用mpv官网列出的shinchiro x86_64构建，版本v0.41.0-1122-gaccb7b282（20261011）。运行install-mpv.ps1下载并校验SHA256后解压到tools/mpv，需要curl和7-Zip。仅本项目目录安装，不修改系统关联。二进制目录被忽略，重新部署需要运行安装脚本；发布安装包时需保留mpv及其依赖的许可证并履行对应开源许可要求。

npm.cmd run verify:mpv使用真实音频静音验证WASAPI、暂停、精确跳转、音量、切片结束、换歌及停止；npm.cmd test另有JSON IPC测试。界面尚未完成自动化视觉验证。


## 核验对比与候选画廊

歌词核验页左右展示原歌词与切片转写，转写标注全曲起止时间，正文差异分别着色。按原歌词起始时间归入切片范围；没有时间戳时按行展示，旧转写没有记录时间的标为“未记录时间”。隐藏音频切片试听控件；底部仍可播放原曲。声学边界不是精确句界，跨句、署名和歌词偏移均可能产生差异。

“重试转写”重新分析整首歌曲，不沿用缓存，支持列表中勾选后批量重试异常歌曲。成功后更新语种、粗LRC和在线候选的本地歌词匹配判断，不额外发出在线搜索请求。重试仍可能出现模型幻觉。

替代搜索弹窗展示歌名、歌手、来源和实际查询关键词，可修改再搜索，并保存所用参数。字段修改仅用于检索、排序，不直接修改任务元信息。三列候选画廊支持箭头、水平滑动，以及画廊聚焦后左右方向键；每次移动一个候选。点击“播放原曲对比”留在画廊中，以mpv进度同时高亮三份候选LRC；点击歌词可跳转。无时间戳候选只显示正文。“选择最终保留”更新任务元信息和歌词，并标记选中候选；源音频不改动。重新搜索之前的选择保留到采纳新候选为止。

验证：npm.cmd test（34项）；node verify-retry.cjs（本地mock ASR与真实FFmpeg验证重新转写缓存覆盖）；node verify-search-parameters.cjs（真实网易云请求验证参数）；node verify-overview.cjs（保留候选与列表状态）。画廊交互未完成自动化视觉验证。


## 歌手标签错误时的检索

采用分级检索：先查“歌名＋歌手”，取5个候选获取歌词。高匹配要求排序分至少0.8、歌名相似度至少0.95、歌手至少0.85、已知时长差不超过12秒、版本一致且有有效歌词；若有可用ASR，歌词相似度也需至少0.8。满足条件则结束搜索，没有高匹配结果才降级“仅歌名”；未填歌手直接只查歌名。

仅歌名检索每个来源最多召回50条，再结合歌名、时长和歌词筛选，保留仅歌名召回的候选席位。降级合并结果按source:id去重，歌词请求复用；合并阶段降低歌手排序权重，不自动认定歌手不同的候选正确。画廊显示实际查询过程与是否降级，提示可能的歌手标签错误或翻唱，供试听后手动保留。

当前歌手来自文件标签，ASR不鉴别歌手声音身份。38项测试覆盖分级搜索、错误歌手、查询失败和跨查询去重。界面尚未完成自动化视觉验证。

实际接口验证：Hard Love 的歌手改为错误值后，成功触发降级，并通过仅歌名检索召回 Ellie Drennan 候选。


## 列表排序与同曲音质版本

可通过表头或排序下拉按歌曲、歌手、专辑升降序；中文排序使用zh-CN、数字自然排序，分页前排序。列表显示格式与kbps，元信息弹窗显示编码、采样率、位深与声道。扫描选择音频流读取，不将内嵌封面当作音频。流码率不可得时使用容器平均码率并标注；VBR/FLAC等平均码率不代表音质评分。

同歌名、同歌手且时长差不超过3秒标为疑似重复，忽略标题中的常见音质标记，保留Live/Remix等版本差异。跨专辑可归组，未知歌手不据此分组。不同格式/编码/采样率/位深/声道或有损码率档位标为不同音质/格式；相同无损格式仅压缩码率不同不作为音质差异。详情可对比同组文件并切换查看，“疑似重复 / 同曲版本”筛选可集中检查。未使用音频指纹或自动删除。

旧记录点击“补充音质信息”：有勾选时读取选中歌曲，否则补齐所有缺少参数的记录。后台任务有进度和停止入口，不重跑歌词识别或在线搜索。46项测试及verify-quality.cjs真实FFmpeg扫描、质量补充任务和重复详情接口验证通过；界面尚未完成自动化视觉验证。


## ASR状态、进度和跳过策略

ASR执行状态独立于歌词匹配结果：未识别、排队中、识别中、识别完成、识别错误。正文不一致仍可识别完成；接口/解码失败或已知重复转写、输出截断异常显示识别错误。列表和详情显示状态及错误说明，可按ASR状态筛选。提交即展示任务进度，识别时按片段更新单曲及总体进度，显示当前阶段、片段数、跳过数、失败数。

“跳过已识别”默认勾选，正常提交不重跑已完成的ASR；自动整理仍会按差异执行搜索。取消勾选可强制重跑，“重试异常转写”始终强制执行。全选均已识别时直接返回跳过数，不调用模型。取消后还在排队的歌曲恢复先前状态，客户端重启发现中断的识别会标为识别错误以便重试。

50项测试通过；verify-asr-progress.cjs使用真实音频与本地mock模型验证默认跳过、片段进度、强制重试、全部跳过和取消后队列清理。未以真实模型全量重跑，界面尚未完成视觉验证。


## 完整音乐库模式

正式界面移除十首样本入口，“全量扫描目录”扫描指定目录所有支持的音频。扫描并发读取4个文件，显示枚举/读取阶段和数量进度；单文件失败不终止全库。每页1000首仅为显示分页，可点击“选中全部筛选结果”跨页处理全部歌曲，也可清空选择。ASR默认跳过已识别，在线搜索仍只处理提交的选择。

全量扫描保留路径与文件大小/修改时间一致的任务ID、ASR结果和已保留候选，同时更新音质参数；旧样本缺少指纹时按原标签和时长匹配迁移。变化的音频重新作为未识别记录。扫描结果持久化，重启后显示完整库。十首验证数据及测试接口继续保留供回归使用。


## 扫描即时进度

点击全量扫描后立即显示列表顶部扫描提示与动画，先让界面绘制再提交扫描。目录枚举阶段显示已发现数量及不确定进度条；读取阶段显示百分比、已读取/总数、失败数、当前文件和已用时间。每500ms轮询独立/api/scan-progress接口，避免进度刷新重新渲染全部列表；扫描完成后才替换列表数据。进度连接暂时不可用时明确提示并自动重试。扫描按钮显示“扫描中”并禁止重复提交。

verify-scan-progress.cjs用40个真实音频文件验证扫描POST未结束时进度接口仍响应，能读到处理中及中途数量；保留完整库持久化数据。界面尚未完成视觉验证。


默认每页1000首，D:\Music现有749首可在同一页展示。ASR提交时先绘制不确定进度条、显示选择数量并将任务面板滚到可见位置；提交完成再展示队列与片段进度。第一片段尚未完成时保持动态进度条，避免静止在0%看似无响应。提交过程中暂停普通任务轮询，防止旧任务状态覆盖提交提示。


## GPU ASR 与达标跳过

运行 `install-asr-gpu.ps1` 安装官方 llama.cpp b11552 CUDA 13.4 及对应运行库，按 SHA256 校验。GPU 文件位于 `tools/llama-cuda`，原 CPU 文件保留。`start-asr.ps1` 默认监听 8082（客户端及启动入口同步使用此端口），使用 CUDA0、GPU 模型层及 4 槽位，每槽上下文 2048（默认总上下文为槽位数 × 2048，可通过 -ContextSize 覆盖）；`-Cpu` 可回退，`-Parallel` 可指定服务槽位数。客户端 ASR 并发仍通过「目录与设置」保存，增加槽位不会自动增加客户端并发。

自动整理及批量搜索跳过已有有效转写且当前歌词相似度至少 80% 的歌曲；重新比较当前歌词，避免沿用旧分数。转写错误、异常、无正文或不匹配的歌曲继续处理。自动整理刚识别达标后同样跳过搜索，即使专辑等字段缺失或旧候选存在差异。手动详情搜索仍可主动查询。达标指歌词正文相似度，尚不代表时间偏移达标。

`node verify-asr-gpu.cjs` 从已扫描音乐库取 4 首各 18 秒片段并发验证，记录识别结果、耗时与 GPU 总显存峰值到 `data/gpu-verification/report.json`，不修改库状态。

4 路 GPU 验证已通过：4 首不同歌曲各18秒片段，转写总请求耗时约1.7秒，GPU总显存峰值6634MiB，含桌面和其他应用。该测试证明4路可用，不代表更高并发上限或全曲质量。

ASR 片段容错：流式接收转写，连续机械重复20次提前中止。首次片段输出预算按每秒20 token、最低128最高512设置；异常片段补入前后各0.5秒上下文自动重试一次，重试预算512，全局重试上限2。服务连接失败后不继续对同首剩余片段请求。每片段记录state、attempts、错误、输入边界和首字/总耗时。正常片段保留，剩余失败时整曲状态为部分识别完成、评分为空，候选歌词评分不使用不完整转写。重试错误/部分歌曲只补跑异常和未完成片段；正常已完成歌曲强制重跑仍重识别全曲。旧错误按每轮重新汇总，左右对比显示异常片段原因。
